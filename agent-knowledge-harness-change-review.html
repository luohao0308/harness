如何启动本地前后端

1. 后端 API

cd services/api-server
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

如果 8000 被占用，换端口后记得同步前端 VITE_API_BASE_URL。

2. 前端 Console

cd apps/agent-console
VITE_API_BASE_URL=http://127.0.0.1:8000 npm run dev -- --port 5173

打开 http://127.0.0.1:5173。开发 token 默认走 dev-engineer-token。

前端手动测试步骤

步骤 1：在 Agent Studio 添加知识

  1. 打开 http://127.0.0.1:5173/agents。
  2. 在 Knowledge Scope 选择 default。
  3. 在 Knowledge Harness 表单里填入名称、标题，并把下面“测试知识文本”粘贴到内容框。
  4. 点击 Add Knowledge。

步骤 2：在 Workspace 提问

  1. 打开 http://127.0.0.1:5173/agents/default/workspace。
  2. 切到普通 chat 模式。
  3. 提问：What does the Apollo Jade release rule require?
  4. 观察 assistant 回答、sources 和消息气泡下面的 grounding badge。

步骤 3：测试证据不足时的提示

  1. 在同一个 Workspace 提问一个知识库里没有的问题，例如：What is the migration rule for Solar Mango?
  2. 预期会显示本地证据不足，不会追加模拟 [web-1] 来源。

步骤 4：在 Run Detail 查看证据链

  1. 发送 Workspace 问题后，进入对应 Run Detail 页面。通常可从 Run 历史或当前消息关联的 run 打开。
  2. 找到 Knowledge Grounding 区域。
  3. 检查 Retrieval Hits、Citations 和 local status 是否能对应起来。

预期效果

Agent Studio

  • Knowledge Sources 里出现新 source。
  • 状态是 ACTIVE。
  • 下面有 document 卡片，显示版本号，例如 v1。
  • document 显示 chunk count 和 INDEXED 状态。

Workspace

  • assistant 消息会出现 grounding badge。
  • 本地命中充足时 badge 文案类似 Local knowledge grounded the answer.。
  • 证据不足时 badge 文案类似 Local knowledge is insufficient; no web research provider is configured.。
  • 本地命中充足时回答末尾包含可追踪 source key，例如 [1]。

Run Detail

  • Knowledge Grounding 区显示 vector capability、hit count、grounded 状态。
  • Retrieval Hits 展示 source kind、rank、score、chunk id、snippet。
  • Citations 显示 citation key，并映射到 retrieval hit。
  • Web Fallback 展示 URL、title、snippet、status。

防幻觉行为

  • 模型输出不存在的 citation，例如 [999]，服务端会替换为 [unsupported-citation]。
  • 服务端会补齐缺失的有效 citation key。
  • 最终 emitted 文本里的 [n] / [web-n] 必须能映射到该 run 的持久 citation record。

后端 API 快速验证

创建知识源

curl --noproxy '*' -X POST \
  http://127.0.0.1:8000/api/agents/default/knowledge/sources \
  -H 'Authorization: Bearer dev-engineer-token' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Apollo Jade Manual Test",
    "description": "Manual test source",
    "source_type": "markdown",
    "title": "Apollo Jade Release Rule",
    "content": "Apollo Jade release rule requires two named reviewers, a rollback note, and a visible evidence link in Run Detail. Apollo Jade release rule requires two named reviewers, a rollback note, and a visible evidence link in Run Detail.",
    "mime_type": "text/markdown",
    "idempotency_key": "apollo-jade-manual-test"
  }'

查询知识源

curl --noproxy '*' \
  http://127.0.0.1:8000/api/agents/default/knowledge/sources \
  -H 'Authorization: Bearer dev-engineer-token'

应返回 items，每个 source 包含 latest_documents、版本、chunk count。
