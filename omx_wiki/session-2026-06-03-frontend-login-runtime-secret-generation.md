# Frontend Login And Runtime Secret Generation

Category: `session-log`

Tags: `auth`, `login`, `jwt`, `runtime-secrets`, `deployment`, `frontend`

## Summary

Completed the visible Agent Console login flow, production-safe registration policy, avatar-menu logout, and the deployment-side runtime secret generation path. `HARNESS_SECRET_ENCRYPTION_KEY` remains a server/deployment startup secret and is never generated or exposed in the frontend.

## Delivered

- Protected Console routes with `RequireAuth`; unauthenticated production users are redirected to `/login?next=...`.
- Kept `/login`, `/register`, and `/oauth/callback` public.
- Added `.omx/plans/prd-login-registration-runtime-secrets-v1.md` and `.omx/plans/test-spec-login-registration-runtime-secrets-v1.md`.
- Added `GET /api/auth/config` with `public_registration_enabled` and `oauth_providers`.
- Added `AUTH_PUBLIC_REGISTRATION_ENABLED`; development/test default to public registration enabled, production defaults to disabled.
- `/api/auth/register` now returns 403 without creating users or organizations when public registration is disabled.
- Login page hides "创建工作区" and OAuth buttons unless auth config enables them.
- Register page shows "注册已关闭" and no form when public registration is disabled.
- Replaced the old top-right user pill plus icon-only logout with an avatar menu. JWT sessions show `退出登录`; dev-token sessions show `开发令牌会话` and `使用账号登录`.
- Preserved development dev-token fallback only when no stored JWT exists.
- Updated the frontend API client so stored JWTs are preferred over dev bearer tokens for normal, admin, multipart upload, and chat stream paths.
- Added refresh-failure handling so a 401 followed by failed refresh clears stored tokens and notifies auth state; protected routes then return to `/login?next=...`.
- Added route/API tests for auth guard and JWT-over-dev-token precedence.
- Added `scripts/generate-runtime-secrets.py` to generate `AUTH_JWT_SECRET`, `HARNESS_SECRET_ENCRYPTION_KEY`, and `HARNESS_SECRET_ENCRYPTION_KEY_ID`.
- Added production startup validation for `HARNESS_SECRET_ENCRYPTION_KEY` so missing, placeholder, short, or `dev-only-*` values fail closed.
- Added `HARNESS_SECRET_ENCRYPTION_KEY` / key id to env examples, Compose profiles, Helm Secret/Deployment/Job templates, README, and deployment/first-run runbooks.

## Boundary

- `AUTH_JWT_SECRET` signs login/refresh JWTs.
- `HARNESS_SECRET_ENCRYPTION_KEY` encrypts DB-stored business integration secrets.
- Both are startup/deployment secrets. They are generated by local/deployment tooling, not by Agent Console.
- Public self-service registration is not a production default. Production account creation is first-admin bootstrap plus administrator-managed users for V1.
- Invite-token email onboarding and real OAuth provider callback handling remain outside this V1.
- Local development may omit `HARNESS_SECRET_ENCRYPTION_KEY` and use the deterministic dev fallback; production must configure it explicitly.
- A code-reviewer found the initial refresh-failure gap; after the API client token-clearing/event fix and AuthProvider listener, the reviewer rechecked and returned PASS.
