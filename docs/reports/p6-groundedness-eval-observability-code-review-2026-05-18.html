生成时间：2026-05-18 · 范围：P6 groundedness Eval、回归判定、 Observability 投影、Run Detail 保存 Eval Case 流程，以及前端质量展示。

审查结论

修复后通过 本轮代码审查发现 3 个正确性问题，均已修复并完成回归验证。

严重级别 问题 修复
高 Eval/Observability 的 trace 归一化曾把旧的 selector fallback 当成 fallback evidence observation。 fallback_observed 现在只读取 Eval 已计算的 fallback_observed 字段，保持 P6 匹配规则一致。
高 Run Detail 保存 Eval Case 时曾从 inferred_fallback 自动写入 fallback_expected；该字段描述的是 selector 推断，不是 web/fallback 证据。 Run Detail 现在只根据客观 run evidence 推导 fallback expectation： 存在 web sources，或 retrieval session mode 为 web、 web_fallback、fallback。
中 Observability 先应用 SQL limit，再做 JSON trace 过滤，可能导致 filtered view 漏掉后续匹配的 Eval Result。 Grounding-quality 现在先按 Eval trace 过滤，再应用返回数量限制；新增回归测试覆盖 forbidden_evidence_leaked=true&limit=1。

新增功能

Eval 拥有 GroundingTraceV1

Eval 生成稳定的 grounding trace，包含通过/失败、失败原因、citation keys、 retrieval hit IDs、required/forbidden evidence 字段、fallback 状态、 unsupported markers 和泄漏来源。质量判断只由 Eval 负责。

Forbidden Evidence Leak Gate

forbidden evidence 泄漏只在 Eval 内检查，输入范围是归一化后的 retrieval hits、 prompt manifest evidence、citations、policy/audit payloads 和 model-call binding metadata。 不扫描原始 ModelCall.request_json 和 response_json。

Grounding Metrics 与 Regression

Eval Run 现在输出 grounding pass rate、citation coverage、unsupported marker rate、 fallback mismatch rate、forbidden leak rate、required evidence miss rate、failure totals、 grounding deltas、新增 leak case 和低样本 caveat。

Observability Grounding Quality 投影

GET /api/observability/grounding-quality 只过滤和投影 Eval 已计算的 trace/metric 字段。它不重新计算 grounding quality，也不渲染 forbidden snippets。

前端展示面

Eval Harness 展示 grounding 指标、regression delta、低样本 caveat 和每个 case 的失败原因。 Observability 展示 grounding-quality 卡片、过滤器和结果链接。Run Detail 保存 selector-only 的 grounding contract 到 Eval Case。

前端手动测试步骤

  1. 打开 Agent Console，进入 /evals。
  2. 创建或选择一个包含 Run Detail 保存 case 的数据集，case 需要有 grounding evidence。
  3. 运行一次 Eval，确认最近运行显示 Grounding、Citation、Forbidden leak、Unsupported、Fallback 等指标。
  4. 设置 baseline 后再次运行 Eval，确认回归面板显示 grounding deltas；样本数较少时应显示低样本提示。
  5. 进入 /observability，在 Grounding Quality 区域使用 eval_run_id、dataset_id 或 failure_type 过滤。
  6. 确认 Observability 展示 leak 状态和 leak sources，但不展示 forbidden snippet 原文。
  7. 打开一个已完成的 Run Detail 页面，保存为 Eval Case；检查 Eval Case payload，应包含 citation keys、retrieval hit IDs 等 selector，不应出现自动推断的 forbidden snippets。
