已修复的审查问题

  • Shadow 绑定错误：shadow manifest 不再绑定到实际 ModelCall；只有 authoritative manifest 才作为模型调用上下文证据。
  • 前端预裁剪：useChatStream 不再用 UI 截断结果作为请求正文，改为发送完整 active path。
  • append-only 冲突：从 immutable manifest 移除可变生命周期字段，新增 context_assembly_manifest_lifecycle 表承载 tombstone/retention 状态。
  • Memory 权限：memory list/create/lifecycle 增加 role gate；org scope 仅 admin 可写；run scope 验证 run 所属用户；manual endpoint 禁止伪造 server source_type。
  • RAG evidence 哈希：v2 RAG section 使用 prompt manifest 中用于 evidence_text_sha256 的同一份 evidence 文本，避免 grounded call 被哈希校验拒绝。
  • Memory 注入包装：memory 文本在 XML-like 标签内 HTML escape；疑似 prompt injection 仍可注入但标记 trust=low 并记录 policy decision。

前端手动验证例子

目标：验证低 token 预算下，后端会裁剪上下文并在 Run Detail 展示 manifest 结果。

  1. 启动后端：cd services/api-server && uv run uvicorn app.main:app --reload --port 8000。
  2. 启动前端：cd apps/agent-console && npm run dev，打开 Vite 输出的本地地址。
  3. 启用 v2：先 GET /api/settings/policies，把返回 JSON 的 context_assembly_v2_enabled 改成 true 后 PUT /api/settings/policies。
  4. 进入 Agent Console 的 Workspace，对同一个会话连续发送 4 到 6 条较长消息，并 pin 其中一条关键消息。
  5. 打开 composer 的上下文窗口设置，把“上下文窗口大小 (标记)”调到较低值，例如 1k 或 2k。
  6. 再发送一句：请总结本轮上下文，并明确引用我 pin 的那条关键消息。
  7. 进入该 Run 的详情页，查看“上下文组装”区块。
  8. 预期：mode 为 authoritative；Included/Omitted 有数值；低预算时出现 token_budget；Pinned 内容仍被保留；Model call 显示 Context manifest ID。

预期效果截图说明

Run Detail 页面应出现一个带数据库图标的“上下文组装”面板。面板中可核对：

  • Manifest：本次上下文组装 manifest ID。
  • Prompt manifest：如果 RAG evidence 被纳入，则展示对应 prompt manifest。
  • Included / Omitted：进入模型请求与被裁剪引用数量。
  • Estimator / Budget：后端使用的 token estimator 与本次请求预算。
  • 黄色提示条：展示唯一裁剪原因，例如 token_budget 或 compression mismatch。
