P3 Web Research 新增功能说明

这个功能让 Agent 在本地知识库证据不足时，可以按组织策略调用真实搜索 provider 补充网页来源，并把来源、策略判断、引用绑定结果保存到 Run Detail，方便用户审计。

一句话总结

新增的是一套受策略门控的真实 Web Research fallback： 本地知识库答不上来时，系统可以调用 Tavily Search 获取网页摘要，但不会自己二次抓取网页正文； 返回结果必须通过 URL/DNS/域名策略检查，合格后才会成为可引用的网页证据。

真实 Tavily provider 默认不抓 raw content post-result policy 强制执行 Run Detail 可审计 source-bound 不等于事实验证

它解决什么问题

  • 本地知识库没有覆盖某个公开网页事实时，可以补充真实来源。
  • 答案引用不再只能依赖 fake fixture 或不可审计的临时结果。
  • 用户可以在 Run Detail 看到来源来自哪里、为什么被接受或拒绝。

它不做什么

  • 不把 provider 返回的 URL 再交给后端二次 HTTP fetch。
  • 不默认保存无边界网页正文。
  • 不声称网页内容一定真实，也不声称 citation 一定支持所有 claim。

功能链路

1. 先查本地知识库 本地证据足够时直接回答，不触发外部搜索，也不消耗 provider 调用次数。
2. Pre-call 策略门控 检查 provider、API key、query 长度、secret pattern、allowlist、timeout、max_results 和 per-run 调用上限。
3. 预留调用账本 在 web_research_attempts 里按 (run_id, call_slot) 记录调用预留，避免并发绕过次数限制。
4. 调用 Tavily Search 只消费 Tavily 返回的 title、url、snippet、score、provider metadata；默认 include_raw_content=false。
5. Post-result 策略检查 标准化 URL，拒绝私网、本地、metadata、credential URL、denylist 或 allowlist 外来源，再持久化 citation。

用户能看到什么效果

  • 聊天结果可以带有真实网页来源，而不是 fake fixture。
  • Run Detail 会展示 provider、accepted/omitted source、citation count、policy decision 和时间戳。
  • 被拒绝的网页不会成为引用，审计里只保留安全摘要，例如 URL hash，不泄露原始敏感 URL。
  • 当 provider disabled、missing key、policy denied、timeout 或 rate limited 时，会产生明确失败状态。

核心安全收益

  • provider-side domain filter 只当作优化，真正安全边界在本系统 post-result policy。
  • fake provider 被限制在开发/测试场景，不能伪装成真实 web evidence。
  • 策略决策保存 snapshot，Run Detail 不靠当前设置反推历史结果。
  • query 默认最小化发送，不把本地私有文档内容拼进 web query。

重要语义边界

Source-bound 不是事实验证。 它只表示真实 provider 来源已通过策略、被持久化，并且答案 citation 能绑定到该 source。 它不表示网页内容一定正确，也不表示每一句回答都被该 citation 充分支持。

前端手动操作例子

  1. 打开 Agent Workspace。
  2. 输入：请基于 OpenAI 官网资料，说明 OpenAI API 是什么，并给出来源。
  3. 等待回答完成后，打开该 run 的 Run Detail。
  4. 检查「知识依据」或来源区域：provider 应显示真实 web research/Tavily，fixture evidence 应为否。
  5. 检查网页来源列表：应能看到 accepted source，例如 https://openai.com/ 相关来源。
  6. 检查策略审计：accepted source 有 allowed decision；如果某个 URL 被拒绝，会显示 omitted/denied 原因。

剩余注意点

P3 当前刻意限定为“消费 provider 返回的摘要/内容字段，不做后端二次抓取”。 如果后续要让系统自己 fetch 网页正文，需要单独做 P4 crawler/fetcher 安全设计。
