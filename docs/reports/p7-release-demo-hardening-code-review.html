审查结论

本次审查覆盖 P7 新增的 Knowledge demo seed、迁移/恢复 smoke、前端 release smoke、runbook 与进度文档。初始 code-review 发现 2 个高优先级问题和 2 个中优先级问题； 已全部修复并复跑验证。

修复 1：迁移/恢复 smoke 外部数据库防护

默认路径现在只使用临时 SQLite；裸 DATABASE_URL 被忽略。 若使用 HARNESS_P7_DATABASE_URL 或 --database-url 指向服务库， 必须显式传入 --allow-service-db-mutation。

修复 2：demo seed 幂等副作用

seed 现在先读取现有知识源并校验确定性 source/document/chunk contract； 已存在且有效时不再重复 POST，避免重复 ingestion 任务和事件。

修复 3：release smoke 自启动

npm run e2e:smoke:release 现在显式启动 Vite、等待 5177 可用、 再运行 Playwright，并在退出时清理本地服务。

修复 4：前端 fixture 合约

P7 org-scoped source fixture 现在包含与真实 seed/readback 一致的 indexed document、 deterministic URI 和非零 chunk count，并在 Agent Studio smoke 中通过交互验证。

新增功能

公共 API demo seed

scripts/seed-knowledge-demo.py 创建 agent 与 org 两个确定性 Knowledge source，并补齐 agent 侧 grounding support document，验证 readback、document URI、 idempotency key 和 chunk count。

迁移/恢复 smoke

scripts/smoke-test-knowledge-migration-restore.py 默认在临时 SQLite 上执行 Alembic head，验证 Knowledge/RAG 表和 retrieval/citation selector 连续性。

前端 release smoke

knowledge-demo.smoke.spec.ts 用 mock route 覆盖 Agent Studio、Workspace、 Run Detail、Eval 和 Observability 的 P7 demo 投影。

runbook 与进度记录

Deployment、Troubleshooting、Web Research runbook 与任务进度记录补充了 P7 release demo hardening 的执行路径和证据边界。

功能作用

P7 的作用是为私有 handoff 提供可重复、低凭证依赖的 Knowledge/RAG demo 信心： seed 数据只走公共 API，迁移 smoke 只证明服务级 schema 与 selector continuity， 浏览器 smoke 只证明前端投影。它不引入新的 Knowledge、RAG、Eval 或 Observability 产品语义，也不把 fixture 证据包装成 provider-backed web verification。

前端手动测试步骤

前置条件：后端或发布负责人已完成 P7 demo seed，前端测试者只验证浏览器可见行为。

  1. 打开 Agent Console，确认浏览器可访问测试环境提供的 console URL。
  2. 打开 /agents，确认 P7 Demo Agent Runbook 与 P7 Demo Org Handoff 均显示为 healthy，并能看到 indexed 文档版本。
  3. 打开 /agents/default/workspace，提交 demo question，确认页面显示 Local knowledge grounded the answer. 并提供运行详情入口。
  4. 打开 Run Detail，确认 Knowledge evidence 区域显示 local knowledge retrieval hit、citation 和 prompt manifest。
  5. 打开 /evals 与 /observability，确认 grounding 指标和质量投影可见。
