Code Quality Findings

1. Capability test invoke still has an unsafe default for high-risk/networked packages

services/api-server/app/api/tools.py creates capability test tasks with enable_sandbox=False and enable_network=False. The PRD requires high-risk or networked package test invocation to be sandboxed or policy-bounded after attachment. Once public package installs exist, this path must not remain a permissive default.

Required follow-up: add a test proving high-risk/networked package test invoke cannot choose an unsandboxed execution path, and document the hard policy in Tool Runtime docs.

2. Package lifecycle contracts are not represented in persistence yet

services/api-server/app/db/models.py currently has Capability, CapabilityVersion, AgentCapabilityAttachment, and CapabilitySnapshot, but no staged package/install approval/rollback/provenance model. Immutable snapshot behavior is present, but activation history and package rollback semantics are not yet separated.

Required follow-up: model a package lifecycle state machine: staged, validated, approved, installed, disabled, rolled back, rejected, uninstalled, with audit refs and immutable historical snapshots.

3. Connector completeness can be overclaimed without a release-state matrix

Existing Knowledge/RAG and web research paths are real, but the accepted plan requires connector labels of exactly usable, configured-but-unavailable, and preview-not-counted. Without a provider matrix, placeholder providers can be mistaken for complete usable coverage.

Required follow-up: add provider release-state documentation and tests proving preview/unavailable connectors do not count toward release acceptance.

4. Remote MCP and skill packages need a manifest boundary independent from OMX internals

Current MCP-shaped tools reuse the ToolRunner path, which is the right foundation. The plan requires importing SKILL.md-style packages and remote MCP configs without coupling runtime behavior to OMX internals or storing raw secrets.

Required follow-up: document manifest fields for package type, transports, permissions, network policy, secret refs, sandbox/test requirements, provenance, and unsupported transport failure.

5. Orchestration evidence must be stronger than assignment existence

Backend and UI already expose orchestration/subagent artifacts, but Phase 0b requires a single operator path where Workspace chat triggers multi-agent/subagent work and Run Detail shows router decision, selected agents, handoffs, reduce result, queue/concurrency, and subagent state.

Required follow-up: add a release smoke assertion that traverses Workspace, Subagents, and Run Detail for the same run id.

6. Token savings must be quality-gated, not only smaller prompts

Context assembly records budget and included/omitted refs. The accepted product requires baseline or shadow comparison, before/after savings, low-cost route reasons, and Eval failure when pruning removes required evidence.

Required follow-up: make savings claims depend on baseline/shadow manifests plus groundedness/eval quality, never on raw token reduction alone.

Phase 0b Vertical Spine Checklist

  1. Stage or upload one private capability package and record package audit.
  2. Stage one public URL/Git package, reject SSRF/private-network targets, pin digest/commit/archive identity, and prove no package code execution during staging.
  3. Create or clone an Agent from the UI/API and persist prompt/model/token-budget config.
  4. Attach at least one MCP, one Skill, one Tool, and one usable knowledge connector.
  5. Run connector sync or reindex and persist connector health, source, document, hit, citation, and policy evidence.
  6. Open Workspace and trigger one automatic or forced multi-agent/subagent run.
  7. Inspect Run Detail for capability snapshot, orchestration evidence, connector evidence, context manifest, and token/cost panel.

Coverage Gaps From Test Probe

  • Marketplace backend has no dedicated CRUD/versioning/attach-detach/rollback suite yet; current coverage lives in tool registry, runner, approvals, and agents tests.
  • Agent Studio and Tool Runtime have page and smoke coverage, but not the future package install, attach/detach, secret binding, or readiness detail workflows.
  • Knowledge and connector tests cover local RAG and web research foundations, but not connector lifecycle, release-state overclaim prevention, secret rotation, or provider health flows.
  • Workspace/subagent coverage exists at backend and Run Detail smoke level; missing browser evidence covers create/cancel/recover lifecycle and concurrency/fan-out behavior.
  • Token/cost coverage validates propagation and context manifests, but not concrete savings thresholds or latency/cost improvement deltas.
  • Release smoke is OMX-independent for current P7 scope, but not yet expanded to marketplace and connector-specific release gates.
