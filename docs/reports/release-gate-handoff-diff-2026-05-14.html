Harness 层能力细分

Model + Harness = Agent

下一步不要只说“加记忆”或“加 RAG”，而是把 Harness 拆成可配置、可审计、可评测的能力层。每一层都要回答：解决什么问题、用什么机制解决、运行证据落在哪。

短期记忆

解决什么
当前 Workspace、会话、分支里的任务状态、用户偏好、未完成决策、最近工具观察。
用什么解决
基于现有 conversation tree、Run events、pinned messages 和 workspace store，新增 session/branch memory projection；进入 prompt 前按 token 预算压缩或剔除。
证据落在哪
Workspace Context 面板显示 included/omitted 原因，Run Detail 记录 memory snapshot、覆盖节点和压缩版本。

长期记忆

解决什么
跨 Run 可复用的稳定事实、组织知识、Agent 偏好、历史决策和可删除的用户资料。
用什么解决
Postgres 持久表：memory_records、knowledge_sources、documents、chunks、provenance、expiry/delete rules；按 organization_id 和 agent_id 作用域隔离。
证据落在哪
Agent Studio 的 Knowledge/Memory 标签页管理来源、更新时间、保留策略；Run Detail 显示命中的长期记忆和引用来源。

RAG / 文档知识

解决什么
让 Agent 回答来自用户文档或内部知识库的问题，而不是靠模型记忆猜。
用什么解决
上传或录入知识源 -> chunker -> embedding adapter -> pgvector 或等价本地检索 -> rerank/threshold -> prompt evidence block。
证据落在哪
每次 Run 记录 retrieval_hits、chunk score、source title、citation span；Eval 可断言答案是否引用了正确 chunk。

本地证据不足与 Web Research

解决什么
本地知识不够时，避免模型编造，同时允许受控补充外部资料。
用什么解决
retrieval confidence gate；低置信度时先声明本地证据不足，再调用 policy-gated research tool；没有真实 provider 时禁止把 mock research 当真。
证据落在哪
ToolCall、Policy decision、source fetch、citation 都进入 Run events，Observability 可筛 fallback rate 和 unsupported-claim rate。

MCP 创建与管理

解决什么
把外部系统能力变成 Agent 可调用工具，并统一走权限、沙箱、审计。
用什么解决
Tool Registry 扩展 MCP server 配置、method schema、secret binding、health check、test invocation；沿用 ToolRunner 和 Policy 流程。
证据落在哪
Tools 页面显示 server/method/risk/sandbox，Run Detail 的 Tool Calling Card 显示输入、输出、耗时、trace id。

Skills / 能力包

解决什么
把可复用工作流、提示词约束、工具组合和验收测试包装成可挂载能力。
用什么解决
skill manifest：instructions、allowed tools、examples、constraints、version、eval cases；Agent Studio 可 attach/detach 和锁版本。
证据落在哪
Run metadata 记录 active skills 和版本；Eval Regression Gate 绑定 skill-specific case，防止技能更新破坏行为。

上下文与 Token 优化

解决什么
在短期记忆、长期记忆、RAG、工具观察和聊天历史之间选择最有用的上下文。
用什么解决
context router + budget allocator；按 pinned、recent pair、retrieval score、memory priority、compression summary 分层装配 prompt。
证据落在哪
Workspace 显示 context ring、压缩率、token saved、included/omitted reason；Run Detail 保存 prompt assembly manifest。

幻觉控制

解决什么
减少无来源断言，区分已知、未知、需要外部检索、禁止回答。
用什么解决
grounding policy：需要事实来源的问题必须带 citation；证据弱时触发 insufficient-evidence path；高风险工具和网络研究走审批策略。
证据落在哪
Eval grader 检查 citation coverage、unsupported claims、fallback correctness；Observability 汇总 hallucination guardrail 命中率。

Eval / 回归门

解决什么
证明 Harness 改动真的提升 Agent 质量，而不是只改善 UI 或单次 demo。
用什么解决
从 Run 保存 Eval Case；新增 groundedness、citation quality、retrieval precision、policy violation、cost/latency 指标。
证据落在哪
Eval Run Results 和 Regression Gate 显示 pass/fail、grader trace、失败样例和关联 Run。

Observability / 审计

解决什么
调试为什么 Agent 这么答：用了哪些记忆、检索了什么、调用了什么工具、花了多少钱。
用什么解决
统一 event sourcing：model_call、tool_call、retrieval_hit、citation、policy_decision、memory_write、context_compression。
证据落在哪
Observability 通过 trace_id 串起 Run、工具、检索、模型调用；Run Detail 提供可回放 timeline。

Policy / Sandbox

解决什么
控制工具、网络、文件、MCP、Web research 的权限边界和副作用风险。
用什么解决
现有 Policy Settings、Tool Registry、WarmPool sandbox 继续作为执行边界；新增知识和 research 操作的 allow/deny/approval 规则。
证据落在哪
Policy decision 写入 ToolApproval 和 Run events；Sandboxes 页面显示资源、租户隔离和复用状态。

Agent Orchestration

解决什么
把单模型回答变成可计划、可并行、可交接、可恢复的 Agent Run。
用什么解决
Plan DAG、Subagent assignments、handoff edges、pause/resume/cancel、event replay；后续把 memory/RAG evidence 注入每个 step。
证据落在哪
Workspace 显示 Plan、Subagents、Tool Calls；Run Detail 显示每个节点的输入、输出、证据和失败点。
