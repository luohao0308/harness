Complete Agent Capability Product 新增能力说明

本文面向产品验收和手工测试，说明本轮新增了哪些能力、解决了哪些实际问题，以及用户如何在控制台页面完成验证。

生成日期：2026-05-19 · 适用项目：Agent Harness · 建议本地访问： http://127.0.0.1:15174，API： http://127.0.0.1:18001。本指南不要求容器路径。

一、新增了什么功能

Agent Studio 可真实创建和克隆 Agent

控制台的 Agent Studio 不再只是展示 Agent 列表，现在可以通过页面调用后端 API 创建 Agent、克隆现有 Agent，并保存模型、提示词、工具和 token 预算等配置。

能力附件可真实写入后端

用户可以把 MCP、Skill、Tool 等能力附加到指定 Agent。后端会创建持久化的 capability attachment，后续运行时按 Agent 作用域解析能力。

工具市场支持三条默认安装路径

Tool Registry 页面现在支持可信 URL 一键下载/安装/启用、任意公网 URL 下载并预检、上传本地文件安装。 高级生命周期信息仍然存在，但不再要求普通用户先理解 manifest、stage、approve、rollback 才能完成可信来源或上传安装。

知识库支持上传文件和外部 API 接入

知识库页面现在只有两个默认入口：上传文件和外部 API。外部 API 首先支持 Dify 风格连接器，后续可以扩展到 RAGFlow、Coze、火山引擎、Notion、Postgres、Ollama 等。

Token 节省采用确定性 baseline

后端现在会记录上下文预算、included/omitted refs、确定性未优化 baseline 估算、实际 prompt/completion tokens、缓存命中和节省比例；Run Detail 与 Observability 都能直接看到这些证据。

能力包下载与安全校验增强

后端对 URL 包执行真实 HTTPS 下载，校验可信 host、公网 DNS 解析、私网/metadata 地址、跨 host redirect、固定 commit/digest、secret_ref 结构、raw secret 泄漏和包 manifest 类型，避免“按钮可点但实际不安全”。

Release Spine 证据门禁增强

完整发布模式下 Phase 0b evidence JSON 不能再静默缺失。只有本地 partial 测试可以显式设置跳过开关。

二、解决了什么问题

之前的问题 影响 现在的解决方式
Agent Studio 前端调用不存在的后端创建/克隆/附件接口。 页面标注 API-backed，但真实点击会失败。 补齐 /api/agents、clone、capability attachment 后端路由，并加测试。
Tool Registry 只有复杂生命周期入口，没有简单安装路径。 普通用户需要先理解 stage / approve / rollback 才能安装能力。 页面新增可信 URL 一键安装、公共 URL 预检后启用、上传安装三条默认路径，复杂字段移到高级信息。
“粘贴 URL 下载”容易变成只记录 URL，没有真实下载证据。 验收时页面看起来通过，但实际没有验证远端包内容、hash 和下载边界。 后端新增受控下载：HTTPS-only、DNS 私网过滤、禁止跨主机 redirect、大小限制、内容 SHA-256 pin，并写入 validation/provenance。
可信 URL 和任意公网 URL 被混成同一种一键安装。 公网包可能绕过人工启用，形成不清晰的信任边界。 可信 allowlist 来源可一键启用；任意公网 URL 只能先预检并返回 staged_capability_id，必须二次点击 Enable。
知识库只有单一路径或者只能靠后台配置。 文件导入和外部 API 接入要分开找入口，测试时很难确认是否真正连上。 现在默认只有“上传文件”和“外部 API”两个入口，Dify 先可用，其他连接器按同一契约扩展。
Token 节省只写在计划里，没有进入运行时视图。 用户看不到省了多少 token、为什么省、实际用了多少。 Run Detail 和 Observability 都新增 estimated baseline、token saved、actual tokens、included/omitted refs 和 cache hit 证据。baseline 不通过在线重复跑一遍实现。
secret 校验函数被重复定义覆盖。 部分错误 secret_refs 结构可能绕过校验。 拆成结构校验和 raw secret 值校验，两个校验都执行。
能力包 id/key 可能超过数据库列长度。 SQLite 测试可能通过，PostgreSQL 上审批失败。 包 key、capability key、version id 全部加长度边界和 hash 后缀。
Phase 0b evidence 缺失也可能通过 release flow。 完整发布可以在没有证据的情况下被误判成功。 full-infra 路径缺 evidence 会失败；local-dev 必须显式 partial。

三、页面测试前准备

当前推荐使用非默认端口启动，避免占用默认开发端口：

# API
cd services/api-server
APP_ENV=development \
DATABASE_URL=sqlite:////tmp/harness-local-nondefault.sqlite \
REDIS_URL=redis://127.0.0.1:6399/0 \
API_BASE_URL=http://127.0.0.1:18001 \
CONSOLE_BASE_URL=http://127.0.0.1:15174 \
MODEL_GATEWAY_BASE_URL=http://127.0.0.1:18001/mock-model \
MODEL_GATEWAY_API_KEY=replace-me \
uv run uvicorn app.main:app --host 127.0.0.1 --port 18001

# Console
cd apps/agent-console
VITE_API_BASE_URL=http://127.0.0.1:18001 \
VITE_EVENT_STREAM_BASE_URL=http://127.0.0.1:18001 \
VITE_DEV_BEARER_TOKEN=dev-engineer-token \
VITE_DEV_ADMIN_BEARER_TOKEN=dev-admin-token \
npm run dev -- --port 15174 --strictPort

快速检查： curl http://127.0.0.1:18001/health 应返回 {"status":"ok","service":"api-server"}。

四、用户如何在页面测试

打开 Agent Studio

访问 http://127.0.0.1:15174/agents。

  • 应看到“智能体工作室”。
  • 应看到“创建 / 克隆 Agent”和“能力附件与就绪检查”。
  • 如果没有已索引知识源，应看到“没有已索引知识源”或“待配置”。

创建一个测试 Agent

在页面上填写：

  • Agent ID：qa-research-agent
  • 名称：QA Research Agent
  • 系统提示词：Answer with grounded evidence and cite run details.
  • Token 预算：保持默认 4096 即可。

点击“创建 Agent”。成功后刷新 Agent 列表，应能看到新 Agent。

给 Agent 附加 MCP 能力

在“能力附件与就绪检查”里填写：

  • 能力名称：mcp_context_search
  • 能力类型：mcp_server

点击“附加到当前 Agent”。成功后 MCP / Skill / Tool 就绪检查应变为通过。

打开工具市场安装页

访问 http://127.0.0.1:15174/tools。

  • 应看到“可信 URL 一键安装”“公网 URL 预检”“上传文件安装”三张默认卡片。
  • 高级生命周期信息应收纳在详情里，而不是强迫先填一堆工程字段。

用可信 URL 一键安装能力

在“可信 URL 一键安装”卡片中填写：

  • Agent ID：qa-research-agent 或 default
  • 可信 URL：https://example.com/customer-research.skill，或配置在 CAPABILITY_TRUSTED_HOSTS 中的 HTTPS 地址。

点击“下载、安装并启用”。成功后应看到 ready state 为 ready 或 attached， package 中应有 pinned_ref、validation_json.download.sha256 和 capability version。

用公网 URL 预检并二次启用

在“公网 URL 预检”卡片中填写：

  • 公网 HTTPS URL：https://example.com/community-skill.skill
  • 固定引用：可以留空；后端会用下载内容 SHA-256 生成 sha256:...。

点击“下载并预检”。预期页面显示 staged_capability_id，但 capability/version 仍为空。 再点击 Enable 后，才会生成 capability version，后续才能 attach 到 Agent。

用上传文件安装能力

在“上传文件安装”卡片中填写：

  • 包名称：uploaded-skill
  • SKILL.md：# Uploaded Skill Run the operator test.
  • Agent ID：qa-research-agent 或 default

点击“上传并安装”，应返回验证摘要、capability/version 信息和后续操作提示；不需要先编辑 manifest JSON。

测试 Agent 作用域调用

在“Agent 作用域测试调用”中填写：

  • Agent ID：qa-research-agent 或 default
  • 工具名：mcp_context_search
  • 测试输入 JSON：{ "query": "release readiness", "limit": 2 }

点击“测试调用”。成功时会显示后端返回结果；失败时会显示明确错误，不会静默吞掉。

验证知识库与 Token 节省

  • 进入 /agents，确认知识库默认入口只有“上传文件”和“外部 API”。
  • 上传一份 Markdown 或文本文件，确认状态变为已索引。
  • 配置一个 Dify 风格外部 API 连接器，确认 secret_ref 不是明文 secret。
  • 进入 /runs/<run_id>，确认“Token 节省”卡片显示预算、baseline estimated tokens、实际 tokens、included/omitted refs、节省和缓存命中。
  • 进入 /observability，确认总览页也显示 token saved、actual tokens、baseline comparison 和 cache hits。

验证回滚、停用和卸载

  • “停用附件”会禁用最近安装的 attachment。
  • “回滚”需要当前包存在 capability/version。
  • “卸载”如果存在启用中的附件，后端会阻止并显示错误；先停用附件后再卸载。

六、验收标准

  • 页面按钮对应真实 API 请求，不再只改变本地显示状态。
  • Agent 创建、克隆、能力附件在刷新后仍存在。
  • 没有已索引知识源时，知识连接器不会显示假就绪。
  • 可信 URL 安装必须执行真实 HTTPS 下载并记录内容 hash；公网 URL 预检必须先返回 staged_capability_id，二次 Enable 后才能生成 runtime capability。
  • 公共 Git 包必须有固定 commit/digest/ref；公网 HTTPS 文件包可以通过下载内容 hash 自动 pin。
  • raw secret 不会被当作合法 manifest 保存。
  • Run Detail 和 Observability 必须能看到 deterministic baseline、token 节省、实际 tokens、included/omitted refs 和缓存命中。
  • 完整发布验证不能在 Phase 0b evidence 缺失时误报通过。

自动验证命令参考： cd services/api-server && uv run pytest -q、 cd apps/agent-console && npm test、 cd apps/agent-console && npm run e2e:smoke:release。
