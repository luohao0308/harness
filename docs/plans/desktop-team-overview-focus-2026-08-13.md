## 目标

把现有 Team UI 与三张参考截图的布局思路融合成两个清晰层级：

1. 默认快速扫描团队，不需要逐个打开 Agent 对话。
2. 需要证据时进入单 Agent 的完整对话，并可按需查看任务结构。

参考图只提供信息组织启发，不复制品牌、头像、窗口 chrome、颜色或具体卡片样式。

## 已确认基线

- 现有 Team API、SSE、mailbox、wake、任务、目标和桌面 IPC 语义保持不变。
- 既有 `协作 / 任务图 / 多列` 三种桌面呈现继续保留，浏览器默认多列不变。
- 2026-08-13 前完成的 P0/P1/P2 Apple/Codex 收敛继续作为视觉基线：连续中性色平面、稳定 `760px` 阅读列、低噪声操作、中文优先和移动端无溢出。
- 参考图 1 强调“并行成员状态 + 系统看板”的全局扫描；参考图 2 强调“对话 + 任务依赖图”的深入判断；当前基线截图仍然偏向单 Agent 会话。

## 最终信息架构

### `协作`：团队概览

默认入口，用于判断团队是否按目标推进。

- 顶部：团队身份、目标状态与完成/总数、`协作 / 任务图 / 多列` 切换、更多操作。
- 中央上部：团队最近活动或阶段摘要，只显示可帮助判断下一步的摘要，不展开完整消息流。
- 中央中部：成员进度列表，每行显示 Agent 名称、角色、执行状态、当前任务、阶段进度和最近结果摘要；点击整行进入该 Agent 的 `专注`。
- 右侧：系统看板，显示当前目标、任务总数/完成数、阻塞与失败、最近活动、需要人工处理的事项。它是聚合状态面，不是第二个聊天区。
- 底部：概览级动作，例如打开当前活跃 Agent、查看全部任务、打开任务图。概览不提供一个模糊的“发送给团队”输入框。

### `专注`：单 Agent 深度对话

从成员行、最近活动或任务负责人进入，服务完整阅读和操作。

- 中央：复用现有 Agent 对话和 composer，保持稳定 `760px` 阅读列。
- 对话能力：完整消息流、流式状态、停止/继续、复制、编辑、分支、上下文压缩、运行详情、文件和审批入口全部保留。
- 辅助面板：默认关闭；打开后显示当前 Agent 的任务详情、最近活动或依赖图之一，不能同时堆叠多个竞争面板。
- 返回概览：保留选中 Agent、概览滚动位置、草稿、未读状态和流式 wake，不重新创建会话。

### `任务图`：结构审查

继续保留现有依赖图能力。它可以从概览右侧打开，也可以从专注模式按需打开，或作为独立全屏视图。任务节点点击后展示负责人和详情，但不在图上直接引入新的任务变更语义。

### `多列`：专家并行模式

继续复用现有 `TeamAgentTabs`、`TeamColumnList`、`AgentColumn` 及每列 composer。它适合需要同时观察多个完整对话的高级用户，作为默认概览之外的明确模式。

## 组件边界

保留并扩展：

- `TeamHeader`：只负责身份、目标摘要、模式切换和全局操作。
- `TeamWorkspaceSurface`：负责 `协作` 概览、`专注` 对话、任务图和多列的编排，不拥有后端数据语义。
- `TeamAgentTabs`：在专注与多列中承担成员切换；概览成员列表只负责比较和进入，不再复制完整导航职责。
- `DesktopTeamMemberRoster`：从会话底部重复成员卡转为概览成员进度列表的可复用行。
- `DesktopTeamInspector`：专注模式的按需 Agent 辅助面板；概览右侧看板使用聚合摘要，不复用完整活动卡列表。
- `DesktopTeamTaskGraph`：任务图视图或按需面板，继续使用现有任务关系投影。

新增的前端职责（不新增后端实体）：

- `TeamOverviewSurface`：聚合摘要、成员进度和进入专注的动作。
- `TeamSystemBoard`：目标、任务、异常和人工待处理项的低密度看板。
- `TeamAgentFocusSurface`：为单 Agent 复用完整对话能力，并管理专注辅助面板状态。

## 三阶段实施

### 阶段 1：信息架构与入口

- 将当前 Electron `协作` 入口定义为团队概览。
- 增加概览成员进度行与“进入专注”动作。
- 将现有单 Agent 协作会话作为 `TeamAgentFocusSurface` 的内部实现，不改消息、任务和 wake 数据流。
- 补充“概览 / 专注”层级的路由内状态或本地状态契约。

验收：默认首屏可看到目标、成员状态、任务完成度和异常；点击成员进入完整对话；浏览器多列和桌面任务图/多列回归不变。

### 阶段 2：看板与按需上下文

- 实现 `TeamSystemBoard`，优先组合现有 Team、目标、任务、事件查询。
- 将最近活动压缩为摘要行；完整活动只在专注辅助面板中展开。
- 在专注模式接入任务详情/任务图按需打开，默认不改变对话宽度。
- 为加载、空状态、阻塞、失败和需要人工处理提供可读文本。

实现结果：`DesktopTeamOverview` 已组合目标、成员进度、最近活动和系统看板；专注对话保留现有消息流/composer，并可在右侧检查器与任务图之间按需切换。切换不会重建 Agent 会话；成员失效时专注状态会自动清理。

验收：不打开对话也能识别阻塞和失败；打开任务图或活动面板不会与完整聊天同时争夺首屏；切换前后会话状态不重置。

### 阶段 3：响应式与视觉复核

- `1440x900` 验证概览、专注、任务图、多列四种状态。
- `1024-1199px` 将系统看板转为抽屉或摘要行，保持对话与 composer 最小可用宽度。
- `390x844` 只保留单 Agent 专注对话，任务图/看板作为临时全幅面板；概览成员项横向滚动且无文档级溢出。
- 提高辅助文字对比度，确保图标操作有 tooltip、`aria-label` 和键盘焦点。

实现结果：1440px、1100px、900px 和 390px smoke 均覆盖；窄桌面专注态保留聊天和返回概览入口，右侧检查器在可用宽度下显示，移动端继续使用单列 Team 对话且无文档级横向溢出。

验收：Team Vitest、Playwright smoke、lint、build、docs/link/diff 门禁通过；Visual Ralph 方向性评分保持 `>=90`，且不出现遮挡、溢出或状态仅靠颜色表达。

## 非目标与回滚

- 不复制参考应用的品牌、头像、窗口外观或视觉皮肤。
- 不新增 Team API、SSE 事件、mailbox 类型、任务实体或桌面 IPC。
- 不把 Team 改成 Run、Trace、Observability 或 Dashboard 产品。
- 每阶段均可通过本地视图偏好回退到现有 `协作 / 任务图 / 多列` 编排；数据层无需迁移。

## 风险

- 现有查询可能无法一次提供系统看板所需的异常聚合；先在前端组合，只有出现性能或一致性问题才新增聚合契约。
- 概览成员行与现有 Agent tabs 可能产生切换职责重叠；必须保持“概览行负责进入，tabs 负责专注/多列切换”。
- 过度展示摘要会重新变成 Dashboard；每个摘要字段必须能对应一个状态判断或下一步动作。
